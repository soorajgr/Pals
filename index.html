    Architecture, privacy, and limitations

    Architecture

    Local input → message parser → rule-based extraction → transparent priority scoring → results linked to source messages. The same parser, extraction and scoring scripts run in the browser, in the optional local server, and in the command-line tool.

    Why rules instead of a cloud model?

    Rules run offline, are lightweight, and can explain each result. This app does not use a language model. Confidence labels describe rule strength, not calibrated probabilities.

    Privacy

    By default there are no network requests, analytics, browser storage, or conversation exports: input and results live in page memory. An optional local server (node server.js) can do the same analysis; it listens on 127.0.0.1 only, the page may connect to its own origin only, and it never logs or stores chat text. Clear removes app-held input and results; it is not a secure forensic memory wipe. Browser extensions, operating-system behavior, and hosting software are outside this app's control.

    Supported message format

    Use “[YYYY-MM-DD HH:mm] Name: message”, “Name: message”, or a WhatsApp text export (Android “09/10/26, 10:30 am - Name: message” and iPhone “[09/10/2026, 10:30:15 AM] Name: message”). In WhatsApp exports, lines without a timestamp continue the previous message and system lines are skipped. In the other format, indented lines continue the preceding message and other lines become separate messages with an unknown author. Slack and Discord exports are not supported.

    Limitations

    Indirect decisions, mixed statements, sarcasm without an explicit marker, and implicit task ownership may be missed. Relative dates, numeric ambiguous dates, and timezone-specific deadlines are preserved but not resolved. ISO dates are compared as calendar dates, not exact instants. An old deadline is not proof that a task is still open.

    Next improvement

    Add a compact on-device model for context-aware extraction while preserving source quotes, uncertainty labels, and offline processing.
