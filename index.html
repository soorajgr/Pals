    Architecture, privacy, and limitations

    Architecture

    Local input → message parser → rule-based extraction → transparent priority scoring → results linked to source messages.

    Why rules instead of a cloud model?

    Rules run offline, are lightweight, and can explain each result. This app does not use a language model. Confidence labels describe rule strength, not calibrated probabilities.

    Privacy

    No network requests, backend, analytics, browser storage, or conversation exports. Input and results live in page memory. Clear removes app-held input and results; it is not a secure forensic memory wipe. Browser extensions, operating-system behavior, and hosting software are outside this app's control.

    Supported message format

    Use “[YYYY-MM-DD HH:mm] Name: message” or “Name: message”. Indented lines continue the preceding message. Other lines become separate messages with an unknown author. This is not a native Slack, WhatsApp, or Discord export parser.

    Limitations

    Indirect decisions, mixed statements, sarcasm without an explicit marker, and implicit task ownership may be missed. Relative dates, numeric ambiguous dates, and timezone-specific deadlines are preserved but not resolved. ISO dates are compared as calendar dates, not exact instants. An old deadline is not proof that a task is still open.

    Next improvement

    Add a compact on-device model for context-aware extraction while preserving source quotes, uncertainty labels, and offline processing.
